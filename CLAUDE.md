# Проект

Три в ряд с перетаскиванием шара (как в Puzzle & Dragons) на Vue 3 и Three.js. Новая версия игры из
`v1_666.io/client/app/components/Page/Mad` (там был pixi.js, тормозил на телефоне). Без спрайтов: шары это
3D-сферы с шейдером «кристалл со звёздами» по мотивам кубиков из `pkt-dice`. Пока играбельное ядро: без фона, врагов и бонусов.

Домашняя страница проекта: https://666.io, указываем её в README (раздел «Мы» / «Us») и в `homepage` в `package.json`.

## Команды

- `npm run dev` : игра (в `.claude/launch.json` порт 5175; на телефон: `npm run dev -- --host`)
- `npm test` : vitest, тесты лежат по слоям: `tests/shared`, `tests/static`
- `npm run build` : vue-tsc и vite build
- `npm run screenshot` : `docs/media/*.png` для README (нужен Chrome или Edge; играет партию через `window.stage`, время крутит вручную)

## Устройство

Общий слой и режимы, подробно в `docs/modes.md`. Читать перед тем, как добавлять режим или трогать `Stage` и `TileLayer`.

| Слой | Что делает |
|---|---|
| `src/shared/core/` | Чистый TS, без Vue и Three. Поле, кластеры, фигуры (`shapes.ts`), путь шара, зерно. Тестируется. |
| `src/shared/render/` | Three.js: `Stage` (камера, кадры, ввод), `TileLayer` (шары), шейдеры, искры, плита, полоска времени, твины. Логики режима тут нет. |
| `src/shared/mode.ts` | Интерфейс режима `GameMode`: что сцена умеет просить у режима. |
| `src/static/` | «Классика»: пошаговый режим. Логика (`game.ts`, `resolve.ts`) и показ (`StaticMode.ts`). |
| `src/dynamic/` | «Живой»: ввод не блокируется. Симуляция (`sim.ts`, тик 1/60 с, без Three и Vue) и показ (`DynamicMode.ts`). Правила в `docs/modes.md`. |
| `src/modes.ts`, `src/components/` | Реестр режимов, меню и экран игры. Объекты Three не кладём в `ref`/`reactive`. |

Главный принцип как в `pkt-dice`: логика не знает про экран, экран догоняет логику. В static логика сначала решает всё: `Game.release()`
возвращает `Resolution` (шаги: что лопнуло, что упало, что насыпалось), `StaticMode` анимирует шаги. В dynamic логика это живая
симуляция с шарами-сущностями, `DynamicMode` каждый кадр читает из неё положения.

### Правила хода (static)

- Схватили шар (`press`), тащим (`drag`): он меняется местами со всеми клетками на пути, в том числе по диагонали.
  Быстрый скачок пальца разбивается на клетки (`pathCells`), шар проходит каждую.
- Во время перетаскивания ничего не лопается. Отпустили (`release`): цепочка «лопнуть, уронить, досыпать» до покоя.
- Кластер: клетка в горизонтальной или вертикальной линии из 3 и более одинаковых. Линии одного типа, которые пересекаются
  или соприкасаются, склеиваются в один кластер (Г, Т, крест). Змейка из трёх без прямой линии не лопается.
- Новые шары сыплются, только когда падение больше не собирает кластеров (случайный новичок не примешивается в цепочку игрока).
- Фигура кластера (`classifyCluster`): кластер должен совпасть с фигурой из `SHAPES` целиком, иначе `null`. Список один и для ядра, и для
  строки в интерфейсе. Собираются только фигуры, где каждая клетка лежит в линии из трёх (Г из четырёх и квадрат не получатся).
- Первое заполнение без троек. Партия повторяется по зерну (`mulberry32`).
- Поле: `row 0` это верх, гравитация к большим `row`.

### Рендер и скорость

- Шары: `InstancedMesh` по одному на тип (`TileLayer`), шесть draw call на всё поле. Материал дешёвый (`gemMaterial.ts`): глубина и звёзды
  считаются в шейдере по преломлённому лучу, блики формулами. Никакого `transmission` (он рисует сцену второй раз) и постпроцессинга.
- Искры (`bursts.ts`): один `Points` на всё, кольцевой буфер, весь полёт в вершинном шейдере по времени. В кадре ни одной аллокации.
- В pixi тормозили фильтры (glow, bloom, blur на каждый спрайт, отдельный проход на каждый). В Three такую ловушку не повторяем:
  эффект на каждый шар отдельным проходом не вешать.
- `devicePixelRatio` ограничен двойкой.
- Новые шары въезжают сверху через `uClipY` в шейдере (клип по высоте поля), без маски. Клип действует только на въезжающие
  шары (`aParams.w`): схваченный шар у верхней границы выступает выше поля и обрезаться не должен.
- Запас кадра вокруг поля (`MARGIN` в `shared/render/Stage.ts`) считается из того, что реально выходит за край поля: рамка, полоска времени,
  выступ схваченного шара (`HELD_OVERHANG` в `metrics.ts`). Добавляешь что-то, что выступает за поле, добавь это в `MARGIN`, иначе холст обрежет.
- Режим сообщает интерфейсу через `ModeEvents`: `onTurn`, `onCluster` (кластер начал лопаться, с фигурой), `onBusy`, `onTimeout`.
- Время хода: `MoveTimer` (чистая логика, тесты) и `TimerBar` (шейдер). Таймер тикает от `dt` кадра, не от часов: стоит вместе с анимацией.

## Правила

- Стиль как в `pkt-dice`: отступ 4 пробела, одинарные кавычки, комментарии и тексты интерфейса по-русски.
- Всё, что лопается, падает или двигается, идёт через `Animator` (`src/shared/render/anim.ts`), а не через `setTimeout`.
- Рендер в превью-браузере Claude программный. Скорость и вид оценивать на реальной видеокарте и на телефоне.
- В dev-сборке `window.stage` это `Stage`, удобно для отладки. В static `stage.mode.snapshot()` против `stage.mode.game.board.toString()`
  проверяет, что экран и логика не разошлись; в dynamic симуляция лежит в `stage.mode.sim`.
- Адрес с `&debug` (например `?mode=dynamic&debug`) показывает кадры в секунду, вызовы отрисовки и память (`Stage.stats`). Если игра кажется медленной, сначала смотри туда.
- В превью-браузере вкладка в фоне даёт около 1 кадра в секунду (`requestAnimationFrame` почти стоит), и анимации «Классики» (они на промисах)
  тогда не идут. Для проверок логики крути время вручную: `stage.animator.tick(dt)` и `stage.mode.update(stage.time, dt)` с паузами между тиками.
